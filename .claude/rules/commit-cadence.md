# 커밋/푸시 주기 규칙

태그 의미는 `backlog-ownership.md` 참고.

## 근거와 권한 범위

사용자가 명시적으로 "주기적으로 commit, push 하도록 규칙을 강제해달라"고 요청했다(2026-09-17). 이는
Claude Code 시스템 지침이 말하는 "사전에 부여된 지속적 권한(CLAUDE.md 등 durable instruction)"에
해당한다 — 그래서 아래 자동화는 **매번 사용자에게 다시 묻지 않고** 커밋/푸시를 수행한다.

**단, 이 권한의 범위는 아래 훅 하나로 한정된다.** 이 규칙이 Claude가 그 밖의 상황에서 임의로
`git commit`/`git push`를 실행해도 된다는 뜻은 아니다 — 사용자가 명시적으로 요청한 커밋(예: "이 변경사항
커밋해줘")이나 이 훅의 자동 체크포인트가 아닌 이상, 여전히 먼저 물어봐야 한다.

## 자동화 내용

- **파일**: `.claude/hooks/auto-checkpoint.mjs`
- **적용 시점**: `Stop` 훅, `update-progress.mjs`(PROGRESS.md 재생성) → `full-quality-check.mjs`(길이/lint/build
  검증) 다음 순서. **[hook]** 앞 단계가 실패(exit 2)하면 이 훅까지 도달하지 않으므로, 커밋되는 코드는 항상
  품질 검사를 통과한 상태다.
- **커밋 주기**: 마지막 체크포인트 커밋 이후 15분 이상 지났고 실제 변경사항(`git status --porcelain`)이
  있을 때만 커밋한다 — 매 턴마다 커밋하지 않는다("주기적으로"의 취지). 커밋 메시지는 `backlog.json`의
  태스크 상태 변화를 자동 요약한다(예: `체크포인트: T-005:todo→doing`). LLM을 호출하지 않는 순수 스크립트라
  이 자동화 자체는 토큰 비용이 없다. **[hook]**
- **푸시 주기**: 커밋이 성공한 뒤, 마지막 푸시 이후 30분 이상 지났으면 현재 브랜치를 `git push origin
  <현재 브랜치>`로 푸시한다. **force push는 절대 하지 않는다** — 실패(네트워크, 충돌 등)해도 조용히
  넘어가고 다음 체크포인트에서 다시 시도한다. **[hook]**
- **상태 저장**: `.claude/.checkpoint-state.json`(gitignore 처리됨, 커밋 대상 아님)에 마지막 커밋/푸시
  시각을 기록한다. 이 파일은 worktree마다 별도로 존재하므로, 각 worktree는 자신의 브랜치를 독립적으로
  체크포인트한다.
- **간격 조정**: 상수는 `.claude/hooks/auto-checkpoint.mjs` 상단의 `COMMIT_INTERVAL_MIN`(기본 15분),
  `PUSH_INTERVAL_MIN`(기본 30분)에서 바꾼다.

## 검증

`/var/folders/.../tmp.*`류 격리된 임시 git 저장소에서 4가지 시나리오를 확인했다(2026-09-17):
변경 없음 → no-op, 커밋 주기 내 재실행 → no-op, 주기 경과+백로그 상태 변화 → 커밋+요약 메시지+푸시,
커밋 주기는 경과했지만 푸시 주기는 안 지남 → 커밋만 하고 푸시는 건너뜀.
